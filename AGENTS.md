# Working on amoris-benchmarks-results

This public repository holds the measured outputs, quality comparisons and validation logs of
[Amoris](https://github.com/qiulinfan/amoris) and of Amoris Pioneer (the private, agent-developed
experimental engine, `qiulinfan/amoris-pioneer`), plus a showcase of the results for people.
Engine code, benchmark programs, specifications and methods stay in the engine repositories
(`docs/bench/`, `docs/charter.md`). Historical results keep their original workload, platform and
date; an archived snapshot is not a new run.

`README.md` is for users (the owner's rule, 2026-10-16): data comparisons as charts and small
tables, scene videos, one licenses line. It carries no commit SHAs, source tables, sanitization
notes or agent instructions. Everything agents need is here.

## Layout

| Path | What it holds |
| --- | --- |
| `README.md` | The user-facing showcase. |
| `AGENTS.md` | This file: sources, publication policy, how to add a source, charts, media, licensing. |
| `charts/*.svg` | The README's charts, generated by `tools/make_charts.py`; never edit them by hand. |
| `tools/make_charts.py` | The chart generator (Python standard library only). |
| `media/` | Showcase videos and their posters, copied unchanged from the engine's public site media. |
| `sources/<origin>-<date>/` | Archived raw results, one directory per source (table below). |
| `LICENSES/` | The engine's MIT license and the third-party asset licenses and credits. |

`.gitattributes` marks `sources/**` and `LICENSES/**` `-whitespace`: recorded output and upstream
license text are data and keep their formatting. `.gitignore` keeps local state, credentials and
publication-check reports (`*gitleaks*.json`, `*privacy-check*.json`, `*checksum-inventory*.json`,
`*hash-audit*.json`) and `/.private-originals/` out of Git.

## Publication and sanitization policy

Everything here is public. Before a file enters `sources/`, `media/` or `charts/`:

- **No local paths, user or host names, or endpoints.** Replace them with `<local-path>`,
  `<local-user>`, `<local-host>` and `<local-endpoint>` (`<redacted>` for anything else private);
  a path inside the Pioneer checkout keeps its part below the checkout root.
- **No process inventories.** Process names, full command lines, PIDs and native thread IDs are
  removed from condition records and logs. Condition JSONs (`tools/machine_conditions.py` output)
  carry a sanitization block: `"sanitization": {"source_file": ..., "source_commit": ...,
  "policy": "Public numeric conditions only; ..."}`.
- **No credentials, emails or private setup context.**
- **No checksum, audit or file-digest provenance records.** Local verification may hash files in
  ignored storage; Git keeps source URLs, licenses and commit references. Runtime content
  addressing, cache identities, world-state and coverage hashes keep their diagnostic meaning.
- **No unsafe screenshots.** A UI capture that shows a local path, endpoint or private context is
  omitted, never edited; originals stay in ignored `.private-originals/`. Editor screenshots and
  recordings that show a local endpoint stay local.
- **No uncleared comparisons.** Nothing measured against Unreal Engine 5 or Unity/PhysX (numbers,
  charts or "within x%" claims) is published until the owner clears it; output of untested
  harnesses is omitted.
- **Metrics are never recalculated.** Public copies keep the recorded values; public game tasks
  and model responses are kept. Historical shell wrappers contain anonymized paths and are not
  ready-to-run commands.
- **Large raw artifacts stay local:** frame pairs, frame and RenderDoc captures, raw float
  readbacks, most frame traces and poll samples, profilers' raw samples, binaries, WebAssembly
  builds, build trees and copied source trees. Each table row says what stayed local; the
  original source records remain available locally.

Privacy reviews, exclusion inventories and secret-scan reports are kept outside this repository.
A quick check of the text files before committing (it should print nothing; images and video
still need a look):

```sh
grep -rIlE 'C:\\\\Users|C:/Users|/Users/[a-z]|/home/[a-z]|127\.0\.0\.1|localhost:[0-9]|[A-Za-z0-9._%+-]+@[A-Za-z0-9-]+\.[A-Za-z]{2,}' \
  sources charts tools README.md
```

## Adding a source

1. Copy the sanitized results to `sources/<origin>-<date>/`: `<origin>` is `pioneer-<track>` for
   a Pioneer exploration track (its `out/<track>/` layout kept below it) or `amoris[-<topic>]` for
   the main engine; `<date>` is the archive date, `YYYYMMDD`. Never rewrite an archived source
   except to fix a sanitization miss.
2. Add a row to the table above: origin repository, branch, commit (and merge commit if any),
   contents, and what stayed local.
3. Add a user-facing entry to `README.md` only if the source adds a comparison or media worth
   showing; otherwise the README does not change.
4. Commit with `Source-repository:` and `Source-commit:` trailers naming every source commit, as
   the history does. This repository is pushed by the owner or an orchestrating agent after
   review.

## Charts

`python tools/make_charts.py` rewrites every `charts/*.svg`; it needs only Python 3. Each chart's
numbers sit in the script with a comment naming the engine document and section they come from.

- Take numbers only from quiet or final measurements recorded in the engine's `docs/bench/*.md`
  or `docs/charter.md`, never from provisional tables, and cross-check them against the archived
  raw data in `sources/` where it exists. Never recompute: a ratio or average appears only if the
  document states it.
- Each chart and its README caption state the hardware, backend and date and link to the specific
  method page in the public engine repository. A Pioneer-only result whose page Amoris does not
  have yet says that the method page follows and links its quiet run data under `sources/`
  instead; never link the bare `docs/bench/` tree as its method. Today that applies to three
  charts: when Amoris has `docs/bench/shadows.md`, `docs/bench/dynamic-scenes.md` and
  `docs/bench/gizmo.md`, repoint the shadow slice culling, many moving objects and editor latency
  captions to them (check with `git ls-tree origin/main docs/bench/` in an Amoris clone).
- Carry the source's caveats that change how a number reads: what a measurement includes or
  leaves out, readings an engine document later marks as superseded (for example Metal GPU
  timestamps before the 2026-10-10 frame-attribution fix, metal-profiling.md), how the compared
  systems differ, and validity limits such as debug-eval.md's pre-isolation runs.
- The SVGs carry their own light and dark colors (`prefers-color-scheme`) and a `<title>` and
  `<desc>`; the README's alt text repeats the key numbers. Orange marks the reference (another
  engine, off, before), blue Amoris (on, after); gray de-emphasizes in single-series charts.
- Look at a chart after changing it, in light and dark mode, for example with headless Chrome
  (`out/` is ignored): `chrome --headless=new --blink-settings=preferredColorScheme=0
  --window-size=800,400 --screenshot=out/<name>.png "file://$PWD/charts/<name>.svg"` (`=1` for
  light).

## Media

`media/` holds the showcase clips and posters exactly as the engine publishes them in
`qiulinfan/amoris` `site/media/` (recorded 2026-10-05; `site/media/manifest.json` there describes
each capture). GitHub does not play relative-path `<video>` in a README, so each clip appears as
its poster linking to the file. The Bistro and Flight Helmet posters are offline path-traced
stills; the clips are frames of the interactive renderer. `editor.mp4` and its poster are not
copied: they show the editor's loopback endpoint, which the screenshot rule above keeps local.

Third-party assets keep their own licenses under `LICENSES/showcase/` and `LICENSES/town-walk/`,

Ship Medium (CC0). A new clip or image that shows another third-party asset needs that asset's
license files and a credits entry before it is published. These records grant no additional
rights to depicted assets or to third-party model responses.
