Mutations of the per-frame caches and of the forward variants' order against the tests added in
the review follow-up (2026-10-09, RTX 5060, Direct3D 12, the default backend).

Each mutation was applied alone to the worktree, then
    cargo test --release -p pocket-render --test scene_changes --test forward_variants -- --test-threads 1
ran, then the file was restored. Before the follow-up, the first four survived the whole
pocket-render suite (the review's scratch copy: lib 89 passed, plus taa, draw_paths, occlusion,
lod, hiz, rt_shadows, neural_*, skinned_bounds).

            "six added: character 3 covers 0 of the view, a fresh renderer's 0.005462963"
jobskip     skinning.rs: the jobs are written once (`if self.jobs_written.is_empty()`).
            FAILED skinned_characters_added_later_draw_in_their_own_poses:
            "one replaced: character 2 covers 0 of the view, a fresh renderer's 0.0061959876"

            resize that shortens the bloom chain), only when the same slots change.
            FAILED exposure_and_resizes_reach_the_display_transform:
            "resize: 100.000% of the pixels differ" (the exposure check passed)

Unmutated, both files pass on Direct3D 12 and Vulkan on both GPUs and with
